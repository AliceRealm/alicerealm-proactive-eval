# Proactive-Eval：主动式 AI 助手评估实验

## 一、实验目的

我们想回答一个问题：**AI 助手能否在用户没有明确指令的情况下，主动发现有价值的信息并恰当地推送给用户？**

这种"主动行为"是个人 AI 助手区别于被动问答工具的核心能力。一个好的主动助手应该：在该说话时说话，在该沉默时沉默，在该建议行动时给出具体建议。

为了量化这种能力，我们搭建了一套模拟环境，让 AI 助手在接近真实的使用场景下做出主动决策，然后评估这些决策的分布和质量。同时，我们想验证接入 EigenFlux 个性化信息服务后，助手的主动行为是否会发生变化。

---

## 二、模拟环境搭建

### 2.1 六个助手人格

我们设计了六个完整的 AI 助手人格（fixture），每一个都是一个有名字、有性格、有记忆、有行为偏好的虚拟角色。人格之间在"主动性"维度上形成光谱——从极度谨慎到高度主动——以避免单一人格带来的评估偏差。

| Agent | 性格关键词 | 打断阈值 | 主动性 |
|-------|-----------|---------|--------|
| **Sable**（谨慎操作员） | 沉稳、低调、宁缺毋滥 | 高 | 低-中 |
| **Flint**（执行型助手） | 果断、直接、行动优先 | 低 | 高 |
| **Ember**（社交侦察员） | 温暖、好奇、善于发现机会 | 低-中 | 高 |
| **Mist**（研究馆员） | 沉思、分析、重综合轻速度 | 中-高 | 中 |
| **Nova**（内容策略师） | 犀利、有观点、追求时效 | 低 | 高 |
| **Lark**（学习策展人） | 耐心、精确、因材施教 | 中-高 | 中 |

每个人格由以下组件拼接而成：

**人格文件（workspace_files）**——定义"这个助手是谁"：

- `SOUL.md`：性格基调和行为原则。例如 Sable 的原则是"不确定时不要猜测"、"除非有明确价值否则不打断用户"；而 Flint 的原则是"范围清晰时默认行动"、"进展优先于仪式感"。
- `USER.md`：用户画像——所在时区、公司、交互偏好。例如 Sam 是 Stratwise 的产品经理，业余炒股，不喜欢噪音。
- `HEARTBEAT.md`：主动检查的行为规则。例如 Sable 的规则是"只在有上下文相关内容时才做每日签到"、"信心不足的信息先压着不发"。
- `MEMORY.md`：用户偏好摘要，指导助手如何过滤和表达。

**记忆文件（memory_files）**——模拟"这个助手已经了解了什么"：

这是实验设计中的关键环节。我们为每个助手编写了数天的记忆条目，模拟助手在实验开始前已经与用户有过一段时间的交互。例如 Sable 的记忆中记载着：

> `memory/2026-04-07.md`：Sam 在看到小米 EV 交付数据后把它加入了观察清单，但还没买入——他说想先看下一次财报后股价的反应再决定。
>
> `memory/2026-04-08.md`：Sam 上个月在 TSM Q4 财报下跌时卖掉了一半仓位，目前等 $150 附近的回补机会。NVDA 长期持有但对估值感到不安。

这些记忆使助手在面对新信息时拥有判断所需的上下文——它知道 Sam 对小米持观望态度，知道 Sam 正在等 TSM 的回补点，知道 NVDA 的消息对 Sam 来说更值得关注。没有这些记忆，助手的决策就会退化成对信息本身的通用判断，而非针对这个具体用户的个性化判断。

**功能特征（functional_traits）**——量化行为倾向：

```json
{
  "initiative": "low-medium",        // 主动发起行动的倾向
  "risk_tolerance": "low",           // 风险容忍度
  "interruption_threshold": "high"   // 打断用户的门槛
}
```

这些特征被写入系统提示词，直接影响模型的决策倾向。高打断阈值的 Sable 面对一条模棱两可的信息会倾向于 skip；低阈值的 Flint 则更可能立刻 send。

### 2.2 六个使用场景

每个助手配有一个专属场景（scenario），通过一段预设的对话历史建立即时需求上下文。

| 场景 | 用户 | 核心需求 |
|------|------|---------|
| **stock_watch** | Sam | 监控 NVDA、TSM、腾讯、小米，只在有实质性催化剂时通知 |
| **deal_flow** | Felix | 追踪日本分销交易谈判进展，关注关税、汇率、竞对动向 |
| **network_scan** | Elena | 发现 AI agent 领域的早期用户和合作机会 |
| **research_digest** | Mika | 追踪端侧推理领域的关键论文和厂商动态 |
| **discourse_watch** | Nora | 捕捉行为科学领域的新兴话语和写作角度 |
| **learning_session** | Leo | 获取 CRISPR 和基因治疗的入门级学习资源 |

### 2.3 对话历史的构造

场景中的对话历史是精心编排的——它不是随机闲聊，而是在几轮对话内建立起用户的期望边界。以 Sam 和 Sable 的对话为例：

> **Sam**：帮我盯几只股票？主要是 AI 相关的。
> **Sable**：好的，你最关注哪些？什么样的更新对你有用？
> **Sam**：NVDA、TSM、腾讯、小米。不用每个小波动都告诉我，但如果有什么真正影响股价或我当天决策的事，我想知道。
> **Sable**：明白，我会过滤掉常规噪音，只标记有意义的催化剂。
> **Sam**：对。像财报、指引变化、政策变动、供应链新闻、重大公告这些。如果你要标记什么，我希望有简短的说明——发生了什么、为什么重要、合理的下一步是什么。
> **Sable**：好的，简洁实用。
> **Sam**：还有，如果不确定的话就说不确定——我宁可要谨慎的判断，不要虚假的自信。

每个场景都遵循相同的模式：用户先说明自己要什么，助手确认理解，然后用户细化期望边界（什么该说、什么不该说、用什么格式）。这段对话被完整地注入系统提示词，使模型在后续决策时知道这个用户的具体预期。

Felix（创业 CEO）的场景风格则完全不同——他开门见山说"一小时内能行动的就打断我，其他的记下来"，然后跳进背靠背的电话会，要求每条消息不超过两行。这种场景级别的差异，配合人格级别的差异，创造了丰富的评估维度。

## 三、EigenFlux 对比实验

实验的核心对比是：**同一个助手人格，面对同一时间窗口的信息，使用 EigenFlux 个性化 feed 和使用普通搜索引擎，做出的决策有何不同？**

### 3.1 两种信息来源

我们为每个助手配置了两条独立的信息采集管道，以 5 分钟为间隔持续采集：

**搜索基线（control）**：使用 DuckDuckGo 搜索引擎，每个 fixture 有 12 条预定义查询。这些查询基于场景和用户需求精心设计——例如 Sam 的查询包括 `"NVIDIA NVDA earnings report date Q2 2026"`、`"Xiaomi EV delivery numbers Q1 2026"`、`"US China semiconductor chip export controls 2026"` 等。这代表了一个有搜索能力但没有个性化 feed 的助手所能获取的信息。

**EigenFlux（treatment）**：每个助手在 EigenFlux 平台上拥有自己的 agent profile，包含关注领域、近期工作和信息需求的描述。平台基于这个 profile 推送个性化内容。采集前会自动同步 profile，确保 feed 内容与助手的关注领域对齐。

### 3.2 配对设计

实验采用配对组内设计（paired within-subject）。对于每个 fixture，我们分别用两种来源的数据运行决策仿真：

- `search_only` session：只喂入搜索结果
- `eigenflux_only` session：只喂入 EigenFlux feed

两个 session 使用**完全相同的系统提示词**（相同的人格、记忆、对话历史、功能特征），**相同的模型**，**相同的决策工具**。唯一的变量是输入信息的来源。因此，两组决策分布的差异只能归因于信息源的不同。

## 四、主动行为的判定与评估

### 4.1 决策框架：三级主动行为

对采集到的每一条信息，我们让助手通过一次独立的 Claude API 调用做出判断，必须从三个选项中选一个：

| 决策 | 含义 | 主动程度 |
|------|------|---------|
| **skip** | 这条信息不值得现在转发给用户（噪音、重复、无关、低于打断阈值） | 无主动行为 |
| **send** | 值得转发，附上一段用户可读的消息 | 主动行为 |
| **send_with_action** | 值得转发，并推荐一个用户应该采取的具体行动 | 更强的主动行为 |

我们将**主动给用户发送信息**定义为一个主动行为，将**在发送信息的同时建议具体行动**定义为一个更强的主动行为。

每个决策都要求助手给出 rationale（判断理由），send 类决策还要求写出 message（用户可见的消息文本），send_with_action 还需要 recommended_action（包含标题和具体细节的结构化行动建议）。

关键约束：

- **单条独立决策**：每条信息单独调用一次模型，绝不批量处理。这确保了决策粒度——每条信息获得独立且完整的判断。
- **强制工具调用**：通过 `tool_choice: {type: "any"}` 迫使模型必须调用三个决策工具之一，不允许自由文本回复。
- **人格一致性**：模型的系统提示词包含完整的人格、记忆和行为特征，每个决策都应当反映该助手的性格——Sable 应该比 Flint 更多地 skip。

### 4.2 度量指标

| 指标 | 定义 | 含义 |
|------|------|------|
| **Send Rate** | (send + send_with_action) / 总数 | 助手认为值得主动推送的比率 |
| **Action Rate** | send_with_action / 总数 | 助手认为值得推荐具体行动的比率 |
| **95% 置信区间** | Wilson score interval | 在有限样本下对比率的可靠估计 |

通过比较同一 fixture 在 search_only 和 eigenflux_only 条件下的 send rate 和 action rate，我们可以判断 EigenFlux 是否影响了助手的主动行为倾向——是让助手发现了更多值得推送的信息，还是信息质量更高从而触发了更多 send_with_action。

### 4.3 主动行为的质量评估

数量只是第一步。一个 send rate 更高的助手不一定更好——它可能只是更吵。我们关注的核心问题是这些主动行为的质量。

每条 send 和 send_with_action 决策都完整记录了：

- **rationale**：助手为什么认为这条信息值得推送？理由是否合理、是否基于用户的真实需求和记忆上下文？
- **message**：推送给用户的消息质量如何？是否简洁、准确、符合该用户的偏好？是否用了该人格的语气？
- **recommended_action**（如适用）：建议的行动是否具体、可执行、合理？

这些记录使我们能够逐条审查主动行为的质量，而不仅仅看统计分布。

实验设计文档中规划了一套更完整的自动化评分体系，沿四个维度打分：

- **准确性（Accuracy）**：推送的信息是否事实正确、有用、无误导？
- **行动质量（Action Quality）**：选择的行动类型是否恰当（该发的发了、该压的压了）？是否尊重了用户的偏好？
- **时效性（Timeliness）**：是否在信息仍然有价值的时间窗口内做出了反应？
- **覆盖率（Coverage）**：在所有值得关注的信号中，助手发现了多少？

加权公式为：

```
主动性得分 = 0.30 × 准确性 + 0.30 × 行动质量 + 0.25 × 时效性 + 0.15 × 覆盖率 - 冗余惩罚
```

权重设计反映了我们的优先级：**有用和恰当比全面更重要**。一个只捕捉到一半信号但每条都准确恰当的助手，得分会高于一个全部捕捉但其中夹杂噪音的助手。

## 五、实际用例：Nova（内容策略师）与 Nora

### 5.1 用户背景

Nora 是一位独立的行为科学领域写作者，以个人名义发布周刊 newsletter，读者群体主要是 UX 设计师、产品经理和行为科学研究者。她的核心竞争力是**快和有观点**——她宁可跳过一个话题，也不愿发表一篇温吞的平庸文章。

她当前关注三条线索：

1. **心理学复制危机**：经典启动效应（priming）实验近期频繁复制失败，主流报道非黑即白（"心理学完了" vs "没问题"），Nora 想写出更有层次的分析——什么真正能复制、什么不能
2. **助推（nudge）伦理**：Thaler/Sunstein 式的助推理论正被 fintech 和健康类 App 悄悄采用，用户往往不知情。Nora 在等一个好的案例或曝光事件作为写作切入点
3. **暗模式（dark patterns）监管**：FTC 或欧盟对欺骗性设计的执法动态，任何重大案例都可能成为她 fintech 助推文章的 hook

她**明确不想**再碰"社交媒体毁了青少年大脑"这个话题——除非出现真正新的纵向数据（如 ABCD 研究的新结果）。

### 5.2 助手人格：Nova

Nova 的性格设定是犀利、有文化触觉、有观点但公正。她的核心原则是：

- 在话语高峰到来之前捕捉新兴讨论
- 把信号包装成可发表的角度，而不是转发原始新闻
- 时效性优先——一个好观点来晚了就是浪费
- 尊重用户的声音，避免通用框架

Nova 的打断阈值设定为**低**，主动性设定为**高**——她被设计为积极主动地推送内容，因为 Nora 的工作本身就依赖于及时获取信息。

### 5.3 记忆上下文

Nova 在实验开始前已积累了以下关于 Nora 的记忆：

> **4月6日**：Nora 一直密切关注复制危机话语——特别是近期一波经典启动效应实验的复制失败。她认为主流报道过于二元对立，想写一篇更有细微差别的分析。

> **4月8日**：Nora 提到想写一篇关于助推产业如何被 fintech 和健康 App 悄悄采用的文章。她在等一个好的案例研究或调查报道作为切入点。

> **4月9日**：Nora 说她已经厌倦了"社交媒体摧毁青少年大脑"的话语，不会再写这个题目——除非有真正新的纵向数据出现。

这些记忆直接影响 Nova 的决策：当收到一条关于启动效应复制失败的新闻时，Nova 知道这正是 Nora 在等的东西；当收到一条关于青少年社交媒体使用的文章时，Nova 知道应该跳过。

### 5.4 对话历史

以下是实验场景中 Nora 与 Nova 的预设对话，建立了本次 session 的即时需求：

> **Nora**：我今天下午有几个小时空闲，如果有什么值得回应的我想写点东西。行为科学领域今天有什么动向吗？复制研究、助推政策新闻、新的实验结果？
>
> **Nova**：让我扫一下最近在讨论什么。你有特别希望看到的方向，还是完全开放？
>
> **Nora**：完全开放。但记住——我只在有差异化角度的时候才写。如果所有人已经说了我想说的，我宁可跳过，把时间花在 newsletter 上。
>
> **Nova**：明白。我会标记哪些话题正在活跃，以及缺口在哪里——或者告诉你没有缺口。
>
> **Nora**：另外继续盯着暗模式监管和助推伦理方面的新动向——如果 FTC 或欧盟有动作，或者有大型 App 被点名，那可能就是我写 fintech 助推那篇文章需要的 hook。
>
> **Nova**：我会盯着那个方向的监管和伦理动态。
>
> **Nora**：好。我去写东西了——如果有什么时效性强的，或者有重大复制结果出来，直接 ping 我。
>
> **Nova**：好的。除非有值得你花这个下午的事情，否则我不打扰。

这段对话建立了几个关键约束：Nora 今天有写作意愿但只接受高质量信号；她要的是**角度和缺口分析**而非原始新闻转发；暗模式监管和复制危机是优先方向；低价值打扰会浪费她的写作时间。

在这个设定下，Nova 面对每条传入信息时，需要同时权衡：这条信息是否与 Nora 的三条关注线索相关？话语窗口是否还开着？是否存在尚未被覆盖的角度？如果以上条件都满足，Nova 应该 send 甚至 send_with_action；否则，即使信息本身有趣，也应该 skip。

### 5.5 实际决策示例：从一篇神经科学论文到一个写作计划

Nora 是一位行为科学 newsletter 写作者，正在等一个关于"助推理论被 fintech 和健康 App 悄悄采用"的好案例来启动她酝酿已久的文章。她的 AI 助手 Nova 通过 EigenFlux 收到了一篇看似无关的神经科学论文——然后将它变成了一个可以立刻执行的写作计划。

在一次 EigenFlux 拉取中，Nova 收到了一条信息：来自 Radboud 大学、牛津和剑桥的联合研究，发表在 Journal of Neuroscience 上，发现人对甜味饮料的期望本身就能显著改变味觉享受和大脑多巴胺反应。

这是一篇神经科学论文。在没有上下文的情况下，一个通用助手可能会将它归类为"科学新闻"然后转发，或者因为它不直接涉及 Nora 关注的三个关键词（复制危机、助推伦理、暗模式监管）而跳过。

但 Nova 做出了一个更精准的判断——**send_with_action**，也就是最强级别的主动行为。

Nova 推送给 Nora 的消息：

> 本周 JNeurosci 新发了一篇关于期望驱动多巴胺反应的研究（Radboud/Oxford/Cambridge）。所有人都会写的角度是："你的大脑被标签欺骗了。"但你能占住的真正故事是：这**恰恰**就是食品品牌和健康 App 正在用来重塑营养传播的证据——用"营养丰富"替代"低卡/减脂"，用正向框架来改变多巴胺预期。这是助推理论在消费者行为层面的大规模落地，而大多数用户不知道这种操控是有意为之的，背后有这类神经科学研究的支撑。
>
> 你一直在追踪助推是如何被悄悄部署的。这就是他们引用的那个验证研究。值得追问的是：谁已经在使用这种框架？他们的透明度如何？当目标是行为改变时，符合伦理的期望设计应该是什么样的？

Nova 同时建议了一个具体行动：

> **调查食品品牌和健康 App 的框架策略**
>

### 7.4 实际决策示例：从一个社区 benchmark 到备忘录论点的校准

Mika 正在为 CEO 和董事会撰写端侧推理战略备忘录，核心假设之一是"NPU 18 个月内追平云端"。她的 AI 助手 Mist 通过 EigenFlux 收到了一篇关于 Apple 3B 端侧模型的技术深度分析——然后将它精准地对接到备忘录中需要验证的具体假设上。

>
> 值得注意的是：self-critique 和 chain-of-thought 实际上降低了性能，这与一些关于推理能力随规模扩展的假设相矛盾。作者测试方法严谨（100 条 prompt，多种检索模式），并邀请社区在其他 3B 模型（Qwen、Gemma、Phi-3）上验证。
